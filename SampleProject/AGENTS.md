## Toolchain (everything works headless)

`bal` CLI (engine repo: `dotnet build BallisticEngine.slnx`, exe at `BallisticEngine.Cli/bin/Debug/net9.0/bal.exe`):

| Verb | What it does |
|---|---|
| `bal map <project>` | Project overview: scenes, script components, asset inventory. Run this FIRST. |
| `bal schema [--type X]` | Component catalog: every component + member types/ranges. Ground truth, never guess members. |
| `bal describe <scene>` | Scene summary (entity tree + components). |
| `bal scene get/set/add-entity/add-component/remove-*/find` | Block-level scene editing with typed validation. Never hand-edit scene YAML. |
| `bal validate <scene>` | Static check: types, members, refs — run after any scene change. |
| `bal import <project>` | Idempotent asset import (run after adding files externally). |
| `bal assets resolve/refs/list` | Path<->guid, reverse references ("what breaks if I touch this"). |
| `bal simulate <scene> --steps N --watch Entity [--snapshot Entity] [--input script.json]` | Headless play with numeric probes + scripted input; `--snapshot` = full live component state. Assert behavior from DATA. |
| `bal render <scene> [--orbit N] [--idmap]` | Deterministic screenshots; multi-view orbit; entity-ID maps. |
| `bal imgdiff <a> <b> [--out heatmap]` | Perceptual diff with mean + hotspot budgets. |
| `bal query <op> <scene> --points/--pairs` | SPATIAL PERCEPTION over the scene geometry (DXR ray queries): occupancy (inside solid?), classify (open/enclosed/solid), nudge (occupied->free space), rooms (visibility clusters), visibility (clear line of sight). Ask the 3D world, don't guess from pixels. |
| `bal gbuffer <scene> [--out dir]` | Dump raw depth/world-normal/albedo (.bin + manifest.json) — read geometry directly, not the tonemapped pixel. |
| `bal perf <scene>` | Render-perf stats JSON (draws/tris/cull/lights/cpuFrameMs) for autonomous perf work. |
| `bal agents <project>` | Regenerate this file. |

Player env-var harness (`dotnet run --project BallisticEngine.Runtime <project>`):

| Env | Effect |
|---|---|
| `BALLISTIC_SCENE=<Assets/...scene>` | Load this scene instead of the startup scene. |
| `BALLISTIC_SCREENSHOT=<path.bmp>` | Save a frame + `.stats.json` sidecar, then exit (`_EXIT=0` to keep running, `_FRAME=N` default 180). |
| `BALLISTIC_SCREENSHOT_PAUSED=1` | No play mode: bit-exact deterministic frames. |
| `BALLISTIC_DETERMINISTIC=1` | Kill all frame-to-frame variance (TAA/SSGI/volumetric/auto-exposure) — frame 60 == frame 240. |
| `BALLISTIC_IDMAP=<path>` | Entity-ID map: `<path>.json` per-entity screen bboxes + `<path>.bmp` segmentation. |
| `BALLISTIC_FX_SSGI/SSR/SSAO/VOLUMETRIC/DOF/...=0\|1` | Force individual effects for A/B shots. |
| `BALLISTIC_DEBUGVIEW=wireframe\|normals\|depth` | Renderer debug views. |

Live editor control: named pipe `\\.\pipe\BallisticEditor` (newline JSON `{id,method,params}`) or the MCP server `BallisticEngine.Mcp/bin/Debug/net9.0/BallisticEngine.Mcp.exe` (stdio, 16 tools). Remote edits are undoable and behave exactly like human edits.

Structured logs: `Library/Logs/engine.jsonl` (one JSON object per line, truncated per session).

## Working rules
- Reference assets by PATH (`Assets/...`), never invent guids; ids are minted by the tools.
- After scene edits: `bal validate`. After gameplay changes: `bal simulate` with watches. After visual changes: `bal render` + `bal imgdiff` against a baseline.
- Game scripts: lifecycle overrides (`Tick`, `OnBegin`, ...) must be `protected` (not `protected internal`). Compile errors block play, not the editor.
- Prefer numeric verification (`simulate --watch`) over screenshot-staring; use the ID map to ask "what is on screen where".
